# Spec issues
status: informative

Disagreements found while extracting the spec from `docs/architecture.md` and
the Rust reference implementation. Each needs a maintainer decision; until it is
made, the spec records the **code's** behaviour as `draft` and says so at the
citing requirement. None of these changes the safety properties (no replay,
single-use permits, durable-before-effect); they are about naming, resumption
and documentation drift.

| id | area | description | where found |
|---|---|---|---|
| SI-001 | ENG | architecture.md §13.1 Mermaid diagram lacks five legal edges the code has (`readOnlyDispatch→postflight/cancelledSafe`, `dispatching→cancelledSafe`, `checkpointed→confirmedFailed/cancelledSafe`). The spec treats the code table as normative (`state-machines/job.yaml`). Fix: redraw the diagram from the table or delete it. | `crates/arkforge-engine/src/lib.rs JobState::may_transition_to` |
| SI-002 | JRN | Two writers exist for the same journal record kinds: `arkforge-engine::step` (typed helpers, write `externalDispatchStarted`, subject = step id, facts incl. jobId on admit only) and `arkforged::jobs` (the daemon, never writes `externalDispatchStarted`, no `jobId` fact on consuming/receipt/checkpoint records). The daemon is what runs on hardware; the spec records the daemon's order (AF-ENG-011) and lists the helper's extra record as engine-only. Fix: make the daemon use the typed helpers or delete them. | `crates/arkforge-engine/src/step.rs`, `crates/arkforged/src/jobs.rs` |
| SI-003 | CRASH | `CrashDisposition::derive` (engine) treats a permit with a durable intent and no `permitConsuming` as `outcomeUnknown`; the daemon's `recover_job` treats it as resolved (not in `PermitLedger::unresolved()`) and concludes `cancelledSafe`. Both are defensible given the daemon writes `permitConsuming` before any device access, but they disagree, and the engine's function is not what the daemon calls. The spec keeps the engine row (AF-CRASH-R-004, conservative) and documents the daemon policy (AF-CRASH-011). Fix: decide which reading is normative and make the daemon call `CrashDisposition::derive`. | `crates/arkforge-engine/src/recovery.rs`, `crates/arkforged/src/jobs.rs recover_job` |
| SI-004 | ENG | `JobRegistry::cancel` assigns `job.state = AwaitingPermit` directly (bypassing `may_transition_to`) to reach `cancelledSafe` from `preflight`, because `preflight→cancelledSafe` is not a legal edge. Either add the edge or route the cancel differently. | `crates/arkforged/src/jobs.rs cancel` |
| SI-005 | ENG | `readOnlyDispatch`, `rebindWait`, `reconciling` exist in the type table but the daemon never enters them: every step (read-only included) is admitted with a permit; rebind happens inside a provider action; reconcile answers from the journal without a state change. The spec marks these edges `exercised_by_daemon: false`. Fix: either implement the read-only fast path or remove the states from the vocabulary in v2. | `crates/arkforged/src/jobs.rs` |
| SI-006 | REC | A dispatch disposition of `confirmedNoEffect` or `confirmedPartialEffect` moves the job to `outcomeUnknown` (the state) while the record keeps the exact disposition; architecture.md §20.2 says a protocol no-effect NACK is `confirmedFailed`. The spec records the code (AF-REC-007). Fix: decide whether `confirmedNoEffect` should conclude `confirmedFailed`. | `crates/arkforged/src/jobs.rs complete_dispatch` |
| SI-007 | IPC | `proto/arkforge.proto` says `JobEvent.sequence` equals the journal sequence that produced the event; the daemon numbers events with a separate per-job counter (`events.len() + 1`). The spec requires only monotonicity (AF-ENG-016). Fix the comment or the counter. | `crates/arkforged/src/jobs.rs Job::publish` |
| SI-008 | DIG | The `arkforge/v1/device-facts\0` domain is used with at least five different preimage shapes (observation map, admission facts map, raw location id, raw serial bytes, raw descriptor bytes, and a connect key in the standalone HDC port). No collision is exploitable because each use is compared only against the same kind, but a port cannot tell from the domain what was hashed. Consider one domain per preimage in v2. | `crates/arkforge-transport/src/{lib,usb}.rs`, `crates/arkforge-standalone/src/hdc_control.rs` |
| SI-009 | DIG | `Domain::ActionReceipt` is declared but nothing is digested under it; the `receiptDigest` fact carries the dispatch evidence digest. Either define the receipt body or retire the domain. | `crates/arkforge-core/src/digest/mod.rs` |
| SI-010 | YAML | `yaml.rs` documents that anchors, aliases and tags are rejected, but the check only fires when the marker is at line start; `a: &x 1` is accepted as the literal scalar `&x 1`. Fixtures pin the actual behaviour (AF-CONF-YAML-022..024). Decide: reject inside values too (stricter, recommended) or document literal acceptance. | `crates/arkforge-core/src/yaml.rs parse` |
| SI-011 | REC | `reconcileJob` does not move the job through `reconciling`; it answers `stillUnknown` / `nothingToReconcile` from the journal. The provider's `reconcile_read_only` SPI is not wired into the daemon. Spec marks reconcile semantics `draft` (AF-REC-002). | `crates/arkforged/src/service.rs` |
| SI-012 | JRN | `externalDispatchStarted` is only written by the engine helper (SI-002); the daemon's dispatch window is `permitConsuming` → `semanticReceiptRecorded`. The ledger treats both records identically, so recovery is unaffected. | `crates/arkforge-engine/src/journal.rs` |
| SI-013 | PROF | `docs/architecture.md` §18.2 sketches profile keys (`versionRange`, `readDomain.read: characterize-at-runtime` comment form) that the loader does not accept (`minimumVersion`/`maximumVersionExclusive` are required). The published profiles are right; the sketch is stale. | `docs/architecture.md` §18.2 |
| SI-014 | CONF | Fixture gaps: no transcript-replay dispatch suite, no reconcile suite, no receipt-digest suite, no CLI black-box suite, no schema validator in-tree. Tracked in `conformance/README.md`. | — |
| SI-015 | ID | The spec requires `OpaqueId` for fact keys, but `DeviceMode` uses a narrower grammar (`[a-z0-9-]{1,64}`) and `productModels`/`hardwareRevisions` are free text in the profile. The CDDL records each precisely; a v2 could unify. | `crates/arkforge-core/src/{ids,effect,profile}.rs` |
